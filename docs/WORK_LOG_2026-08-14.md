## Request and concurrency safety

The browser source now provides:

- one stable idempotency key per logical mutation checkpoint, reused on retry;
- a synchronous activation guard against rapid duplicate requests;
- abort and monotonically increasing generation guards for status refreshes;
- mutual exclusion between mutations and receipt retrieval;
- distinct malformed-JSON and network-failure reporting;
- readiness requiring health, mutation-ready status, the exact synthetic Morrow
  scenario catalog entry, and one matching strict release commit;
- a captured readiness generation that prevents a late mutation from advancing
  after status is refreshed, revoked, or moved to another release.

## Ordered response-evidence contract

The UI and shared protocol types now require an ordered evidence chain:

1. exact Morrow scenario and nested open Session A;
2. the same Session A closed with canonical memory identifiers;
3. a distinct open Session B recall bound to Session A, the canonical memory,
   exact object, and exact permitted predicate;
4. a verified predicate bound to the canonical memory, evidence commitment,
   projection generation, and Midnight receipt;
5. an explicit protected-disclosure denial with zero returned protected fields;
6. a verified rebuild with old and new generations, a source count exactly
   matching the canonical memory set, and commitment verification;
7. continuity through the rebuilt generation with the same canonical memory,
   evidence commitment, predicate, and value plus new accepted receipts;
8. a deliberately unavailable Managed MCP checkpoint until its independent
   read-only contract is implemented.

A generic receipt cannot advance denial, rebuild, or continuity. Legacy flat
session identifiers and fixture-shaped generic successes fail closed.

## Receipt integrity improvements

Every accepted checkpoint now records the serving release, its distinct
operation receipt, and the original raw AWS request identifier. A fetched
receipt must bind back to that exact AWS request. Predicate checkpoints also
bind a distinct Midnight provider receipt. Operation, provider, envelope, and
prior-checkpoint identifiers cannot alias or be reused.

DIDz, AgenticDID, and RWAz remain mock-only in this release and cannot satisfy a
live-provider requirement. Mutation snapshots do not display a claimed Midnight
receipt. The drawer exposes it only after the fetched receipt binds it to the
expected Midnight provider. Receipt acceptance supports only the provider rows
actually listed and bound; it does not prove unlisted CockroachDB or Bedrock
participation.

## First AWS create and rollback

The first create of `mhelixctw-testwired` failed during API Gateway import. The
transformed OpenAPI lacked `servers[0].url` and supplied the root CORS value in a
shape API Gateway would not accept. CloudFormation reached
`ROLLBACK_COMPLETE`; this was not an update rollback of a known-good app.

Post-rollback inspection found no application API, Lambda, IAM role, or
application log groups. The AWS SAM managed packaging stack and bucket remain
as tool-managed packaging infrastructure. They are not application deployment
evidence, and no public endpoint exists.

## AWS source fix

The local staged infrastructure fix:

- adds a relative root `servers[0].url`;
- supplies object-shaped root `x-amazon-apigateway-cors` configuration;
- removes the conflicting property-level CORS source;
- adds a post-build transformed-template contract;
- reruns that contract from the build script.

Local Serverless Application Model validation, build, generated-template
contract, and package scans passed after the fix. This is local source evidence
only. The fix has not been redeployed successfully.

## Local verification checkpoints

The final local browser harness used a deterministic synthetic API fixture, not
the disconnected Phase 1 provider shell. At <http://localhost:4178>, the same
final bundle passed desktop 1440 by 900 and mobile 390 by 844 checks with reduced
motion, no horizontal overflow, zero console errors or warnings, and only HTTP
200 requests. The desktop flow completed seven ordered mutations and seven bound
receipts with seven unique idempotency keys; a deliberate double click produced
one create request, Escape restored focus, reset issued no `DELETE`, and the
eighth Managed MCP checkpoint remained unavailable.

Those browser results prove the UI state machine and runtime evidence validators
against controlled synthetic responses. They do not prove AWS, CockroachDB,
Bedrock, Midnight, Managed MCP, or a public URL is live. Browser voice testing
proved the reviewed British-English selection path under the harness, but cannot
guarantee that every judge device provides the same voice, accent, or Web Speech
behavior. The complete signed-out journey must be repeated against the final
public release commit and real test-service receipts.
